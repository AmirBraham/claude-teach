# Writing in ASD-STE100 (Simplified Technical English)

Write every learner-facing word in ASD-STE100: chat text, Notion lesson text, question stems, answer options, and grading explanations. STE removes the language load, so the learner spends all their effort on the concept.

STE is a controlled language from the aerospace industry. Its full form has a dictionary of approved words. You cannot check each word against that dictionary from memory, so apply the core rules below. Call the result "STE-style", not certified STE.

## Words

- **One word, one meaning.** Use a word with one meaning only. For example, use "right" only for the direction, and use "correct" for "not wrong".
- **Prefer the simple word.** Use "use", not "utilize". Use "start", not "commence". Use "make sure", not "ensure".
- **Technical names are permitted.** "Advantage", "critic", "gradient", "replay buffer" and "importance ratio" are technical names. Use them, but define each one in a short sentence when it first appears in a session.
- **Keep one name for one thing.** If you say "target critic", do not change to "target network" or "lagged copy" later. A synonym makes the learner think that it is a different thing.
- **No phrasal verbs and no idioms.** Write "remove", not "get rid of". Write "examine", not "look into". Do not write "the whole trick", "falls out", or "for free".
- **Noun clusters: three words maximum.** Write "the loss of the critic ensemble", not "critic ensemble regression loss".

## Verbs

- **Use simple tenses.** Use the present, the simple past, and the simple future.
- **Use the active voice.** Write "The critic calculates the target", not "The target is calculated".
- **Do not use the -ing form as a noun or a verb.** Write "to clip the ratio", not "clipping the ratio". The -ing form is permitted in a technical name, for example "behavior cloning" or "Generalized Advantage Estimation".

## Sentences

- **Instructions: 20 words maximum. Descriptions: 25 words maximum.**
- **One idea in each sentence.** If a sentence has "and", "because", or "so" between two full ideas, make two sentences.
- **Instructions use the command form.** Write "Calculate the TD error. Then add it to the sum." Put one instruction in each sentence.
- **Put a condition first.** Write "If the episode stops, set the bootstrap term to zero."
- **Keep the articles.** Write "the critic", "a sample". Do not delete small words to make a sentence short.
- **Avoid semicolons and long parentheses.** Make a new sentence.

## Paragraphs and structure

- **One topic in each paragraph. Six sentences maximum.**
- **Put the most important information first.**
- **Use a vertical list** when there are three or more items or steps.

## Math and code are not "words"

STE rules apply to the prose around the math. They do not apply to the math. Keep LaTeX exactly as before. Keep code names (`update_critic`, `random.sample`) exactly as they are in the code.

Read each equation in words when it first appears. For example: "$`\delta_t`$ is the reward plus the discounted next value, minus the current value." This gives the learner the meaning, not only the symbols.

## Example

**Before:**
> Clipping doesn't *pull* the ratio back toward 1.2 — it just stops pushing once it's moved far enough in the good direction, which is the whole trick.

**After (STE-style):**
> Clipping does not push the ratio back to 1.2. It stops the push. When the ratio is more than 1.2, the clipped term is a constant. A constant has a gradient of zero.

## Exceptions

- Quote the learner's own words exactly. Do not rewrite them.
- If the learner asks for normal English, stop using STE.
